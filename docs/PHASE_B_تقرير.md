# المرحلة B — إعادة تصميم لوحة المتابعة والتقارير بهوية ARRIVE المعتمدة

## ما تغيّر (عرض فقط)
- `app/index.html`: كتلة tokens مركزية (`ARRIVE-TOKENS`) منسوخة من `design-system/tokens/`، شريط جانبي أزرق داكن على اليمين مع اللوجو الرسمي، هيدر بعنوان الصفحة، كروت مؤشرات (KPICard)، شارات حالة (أيقونة + نص + لون)، جداول بترويسة ARRIVE Blue وترتيب بالنقر، فلاتر مع شرائح الفلاتر النشطة وإعادة التعيين، رسوم أعمدة CSS، حالات التحميل/الفراغ/الخطأ، تقرير جديد قابل للطباعة A4.
- لم يتغير: `Code.gs` و`schema.json` و`data/` و`MOCK` وكل دوال التحقق والـ API ومعرّفات العناصر (أُضيف فقط `pageTitle` و`kpiCharts`).

## افتراضات عرض يجب اعتمادها
1. تصنيف نصوص الحالات إلى (نجاح / قيد التنفيذ / تحت الإجراء / مخالفة / مغلق) في `STATUS_CLASS` — اجتهاد عرض؛ أي حالة غير مذكورة تظهر نصًا عاديًا.
2. شارة «بلغ الهدف / دون الهدف» محسوبة حسابيًا من النسبة والهدف (المطابقة الصباحية والمرتجعات فقط).
3. التقرير لا يحتوي نتائج/أسباب جذرية/توصيات/مواعيد استحقاق لأن المصدر لا يوفرها.

## فجوات في نظام التصميم (لا مكوّن معتمد لها)
FilterBar، Multi-select، Target-vs-Actual، Aging buckets — بُنيت كأنماط محلية بالـ tokens فقط.

## قيود التحقق
- Cairo وFont Awesome يُحمَّلان من CDN المعتمد وهو غير متاح في بيئة الفحص، لذلك لم تُعاين الأيقونات وخط Cairo بصريًا (ظهر بدلهما خط احتياطي).
- حقول التاريخ الأصلية تتبع لغة المتصفح (قد تظهر mm/dd/yyyy) ولا يمكن فرض ISO عليها دون تغيير المنطق.
- ترقيم الصفحات في الطباعة يعتمد على `@page` margin boxes (Chrome يدعمها، Firefox لا).
- الاختبارات المتصفحية الثلاثة (dashboard/admin_ui/xss) تفشل قبل Phase B وبعده بسبب طبقة MOCK (مشكلة قديمة).
