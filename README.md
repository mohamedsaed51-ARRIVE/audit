# ARRIVE AUDIT CONTROL TOWER

لوحة تحكم رقابية لعمليات الشحن في **ARRIVE** (شركة شحن وتوصيل مصرية)، تُستخدم لتسجيل ومتابعة سبعة أنواع من عمليات الرقابة التشغيلية على مستوى الفروع، وربطها بقاعدة بيانات حقيقية على Google Sheets عبر Google Apps Script.

---

## أ. تعريف المشروع

النظام واجهة ويب واحدة (`dashboard/index.html`) تسمح لفريق التدقيق التشغيلي بـ:
- تسجيل سجلات رقابة يومية لكل نوع من الأنواع السبعة، مع تحقق فوري من صحة البيانات (على مستوى الواجهة **و**الخادم معًا).
- عرض مؤشرات أداء (KPIs) وتقارير إدارية مُصفّاة حسب الفرع/التاريخ/المدقق/الحالة.
- كل عملية حفظ تُرسَل إلى خادم Google Apps Script (`Code.gs`) الذي يتحقق من قواعد العمل ثم يكتب السجل في تاب مخصص داخل ملف Google Sheets، مع منع التكرار (idempotency) عبر `clientRequestId`.

## ج. متطلبات التشغيل

| المتطلب | لماذا |
|---|---|
| متصفح حديث (Chrome/Edge/Firefox) | لفتح `dashboard/index.html` — لا يحتاج أي تثبيت |
| حساب Google شخصي أو عملي | لإنشاء Google Sheet ونشر Apps Script Web App |
| Google Sheets + Google Apps Script | التخزين الفعلي وتنفيذ منطق العمل من طرف الخادم |
| Node.js (18 أو أحدث) | **فقط** إذا أردت تشغيل مجموعة الاختبارات المحلية (`tests/`) — غير مطلوب لتشغيل Dashboard نفسه |
| Python 3 + `openpyxl` | **فقط** إذا أردت إعادة توليد ملف Excel الأساسي من `backend/schema.json` (نسخة جاهزة مرفقة أصلًا، فهذا اختياري) |

**لا يوجد أي متطلب بناء (build step)** — `dashboard/index.html` ملف واحد قائم بذاته (HTML+CSS+JS مضمَّنة بالكامل)، بلا أي مكتبات خارجية أو حزم npm.

## د. تشغيل Dashboard محليًا

1. افتح `dashboard/index.html` مباشرة في أي متصفح (سحب وإفلات الملف، أو Right-click → Open With، أو خادم ملفات ثابت بسيط لو أردت — لا حاجة لأي منهما فعليًا).
2. عند أول فتح ستظهر شاشة إعداد تطلب: **رابط Web App** (`/exec` الحقيقي — راجع القسم "هـ" بالأسفل)، و**اسمك**.
3. لن يُحفَظ الرابط في `localStorage` إلا بعد نجاح اختبار اتصال حقيقي (`bootstrap`) — أي رابط خاطئ يُرفض فورًا برسالة واضحة ولا يُخزَّن.
4. بعد نجاح الاتصال، ستظهر الشاشة الرئيسية بالأنواع السبعة وقوائم البحث والتقارير.

لا يحتاج المشروع Node.js أو npm أو Vite لتشغيل الواجهة نفسها — هذه فقط لتشغيل ملفات الاختبار في `tests/`.

## هـ. إعداد Google Sheets وGoogle Apps Script (خطوة بخطوة)

1. أنشئ Google Sheet جديدًا فارغًا (يُفضَّل تجريبيًا منفصلًا عن أي بيانات إنتاجية حقيقية أثناء أول تجربة).
2. استورد إليه ملف `backend/ARRIVE_Backend.xlsx` المرفق (File → Import → Upload → Replace spreadsheet)، أو أعد توليده بنفسك عبر:
   ```bash
   cd backend
   python3 build_backend.py
   ```
   هذا يبني تابات فارغة (رؤوس أعمدة فقط، بدون أي بيانات) لكل نوع من الأنواع السبعة، بالإضافة إلى تابي "الإعدادات" (قوائم منسدلة كالفروع والمدققين) و"`_Sequence`" (عدّاد أرقام السجلات).
3. من داخل الشيت: Extensions → Apps Script.
4. احذف أي كود افتراضي موجود، والصق محتوى `appsscript/Code.gs` بالكامل.
5. من الأعلى: Deploy → New deployment → اختر النوع **Web app**.
   - Execute as: **Me** (حسابك).
   - Who has access: حسب سياستكم الداخلية (عادة "Anyone within [المؤسسة]" أو "Anyone" إن كان لا بد من وصول خارجي — راجع سياسة الأمان الداخلية لديكم قبل الاختيار).
6. بعد النشر، انسخ رابط **Web app URL** (ينتهي بـ `/exec`).
7. الصق هذا الرابط في شاشة إعدادات Dashboard (`dashboard/index.html`) عند أول تشغيل.
8. نفّذ حفظ سجل تجريبي واحد من الواجهة، ثم افتح الشيت وتأكد من ظهور الصف في التاب الصحيح.

**ملاحظة أمان مهمة:** لا يطلب هذا المشروع في أي خطوة كلمة مرور أو مفتاحًا سريًا أو Service Account — الاعتماد بالكامل على جلسة Google الخاصة بك عند نشر الـ Web App، ورابط `/exec` وحده هو ما يُدخَل يدويًا في شاشة الإعدادات (ويُخزَّن فقط في `localStorage` بمتصفحك، وليس في أي ملف يُرفع لـ GitHub).

## و. تشغيل الاختبارات

```bash
npm install                     # يجلب Playwright فقط (اختبارات المتصفح)
npx playwright install chromium # أول مرة فقط — يحمّل نسخة Chromium الخاصة بـ Playwright

npm run test:node       # 68 اختبار Node.js — يشغّل appsscript/Code.gs الحقيقي عبر محاكاة (Sandbox)
npm run test:parity     # 14 سيناريو — يقارن تحقق الواجهة (index.html) بتحقق appsscript/Code.gs
npm run test:browser    # 65 اختبار Playwright — متصفح Chromium حقيقي، متصل بنفس محاكاة Code.gs
npm run test:all        # الثلاثة معًا بالترتيب
```

**النتيجة الموثَّقة من آخر تشغيل فعلي لهذه الحزمة بالذات، بعد نقلها إلى هذا الهيكل الجديد (وليست نتيجة قديمة مُعاد ذكرها):**

| الطبقة | العدد | النتيجة |
|---|---|---|
| Node.js | 68 | 68/68 ✅ |
| Rule Parity | 14 | 14/14 ✅ |
| Playwright | 65 | 65/65 ✅ |
| **الإجمالي** | **147** | **147/147 ✅** |

**مهم جدًا — هذه الاختبارات محلية بالكامل ولا تثبت شيئًا عن Google Sheets أو Google Apps Script الحقيقيين:**
الطبقات الثلاث تُشغِّل نص `appsscript/Code.gs` الحرفي نفسه، لكن عبر محاكاة في الذاكرة (`tests/gs_sandbox.js` — يستخدم وحدة `vm` في Node.js بدل شبكة حقيقية)، وليس عبر اتصال شبكي فعلي بخادم Google. اختبار Playwright يفتح متصفح Chromium **حقيقيًا** ويتفاعل مع DOM الحقيقي لـ `dashboard/index.html`، لكن طلبات الشبكة داخله (`fetch` إلى رابط `/macros/...`) تُعترَض وتُنفَّذ محليًا عبر نفس المحاكاة (`page.route()`)، وليس عبر إنترنت حقيقي. **لا يوجد أي اختبار في هذه الحزمة اتصل فعليًا بـ Google Apps Script أو Google Sheets حقيقيين** — ذلك يتطلب تنفيذ الخطوات في القسم "هـ" أعلاه يدويًا على حساب Google حقيقي، ولم يحدث بعد.

## ز. القيود المعروفة (بصدق تام، بلا تجميل)

- إجمالي الاختبارات المحلية الحالي **147/147**، تم التحقق منه فعليًا بتشغيل حقيقي عند تجهيز هذه الحزمة (وليس رقمًا مُفترضًا).
- **Google Apps Script الحقيقي لم يُختبر من بيئة إعداد هذه الحزمة** — بيئة التجهيز لا تملك اتصالًا شبكيًا بـ `script.google.com` أو `accounts.google.com` (محجوبة على مستوى سياسة الشبكة)، ولا يوجد أي موصل (connector) لـ Apps Script فيها.
- **Google Sheets الحقيقي لم يُختبر** لنفس السبب.
- **Live Integration الحقيقي يحتاج إلى تنفيذ يدوي من جهازك الشخصي**، متصل بحساب Google فعلي وGoogle Sheet تجريبي منفصل عن الإنتاج، باتباع الخطوات في القسم "هـ" أعلاه.
- لا تعتبر النظام "جاهزًا للإنتاج" حتى تُنفَّذ خطوات القسم "هـ" فعليًا وتتحقق بنفسك من ظهور سجل حقيقي داخل Google Sheets.
